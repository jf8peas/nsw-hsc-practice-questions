# Content task prompt for spec 009 (the multi-text question bank)

Paste everything inside the block below into Claude Code once per batch (change the batch number). Batch 0 and the extraction batches may run **in parallel with the marker gate** (`quickstart.md` §2), once the code tasks that read `bank/comparative/` are done: building and reviewing the bank does not depend on the prompt. What waits for the gate is the **release**: no question gets `reviewedOn` until the gate has passed, and step 10's model-answer check is rerun if the gate changes the prompt or the model.

```text
Spec 009 content task, BATCH 1. Build the question bank of the comparative unit (y12-english-advanced-comparative-texts) from the school trial papers in resources/y12_english_advanced_paper1_trial_exams/. Read first: specs/009-english-comparative-short-answers/spec.md (FR-028 to FR-034, User Story 8), plan.md, research.md R2 and R12, data-model.md (§1, §9), and specs/008-english-unseen-short-answers/content-prompt.md and its lessons below. This unit keeps every Section I question that refers to two or more texts, whatever its number (31 found: 21 are Question 5, 10 are Questions 1-4, 16 choice, 15 fixed pair, marks 3 to 8).

Batches (process only the current batch, then stop for my review):
- Batch 0 (inventory only, no bank): inventory the four papers spec 008 never inventoried: Fort St 2023, Fort St 2025, Roseville 2026 (a scan: OCR), North Sydney Boys 2024 (only 8 pages: check whether the stimulus booklet is missing). Then relabel the six single-text Question 5s in their existing inventories from "not_q1_to_q4" to "kept" (Abbotsleigh 2023, Barker 2026, Caringbah 2024, James Ruse 2024, North Sydney Girls 2024 and 2025) and edit spec 008's spec.md FR-040 to "keep every single-text Section I question, not only Questions 1-4" (spec 009 FR-034). Do not build those six questions here; they belong in spec 008's bank (a later 008 content task).
- Batch 1: every paper whose multi-text question is a Question 5 (22 found, so 21 once the St George Girls 2025 Q5 holdout below is excluded).
- Batch 2: every multi-text question in Questions 1 to 4 (11 found, so 9 once the Cheltenham Girls 2023 Q1 holdout below and North Sydney Boys 2024 Q4 (its stimulus booklet is missing) are excluded), plus the multi-text questions in the papers Batch 0 inventoried.
- Never put in the bank or tune to: St George Girls 2025 Q5 and Cheltenham Girls 2023 Q1. They are the marker's frozen holdout (they are used only by the pilot's holdout set, and only after the gate's tuning is done). Their inventory entries say "reserved_holdout".

For each paper in the batch:
1. Inventory. Read the question pages themselves, not only extracted text. For every multi-text question record: number, marks, the texts it refers to with each text's form, and whether the student chooses. A fixed pair names both texts ("Compare how Text 4 and Text 5 ..."). A choice question gives the fixed text if any, the texts to choose from and how many to pick ("Text 5 and ONE other text", "any TWO of Texts 1 to 4"), written as choice: { fixed, from, pick }. Update resources/english-unseen/inventory/<school>-<year>.json (additive: keep every existing field and entry; change only the multi-text entries from "skipped / two_or_more_texts" to "kept", or keep them skipped with a reason from the report script's list).
2. Texts. First look each text up in the shared store (content/units/y12-english-advanced-unseen-texts/store-texts.ts; the bank files in resources/english-unseen/bank/ show which exist). A text already stored is pointed at by its id; never extract it twice. Extract only a new text, with spec 008's rules unchanged: verbatim layout (poem lines and stanza breaks and line numbers, prose paragraphs), the heading as printed, title, author, source line, footnotes as "word: definition" with no inline markers, checked line by line against the page image. A visual: crop it, check its description (below), file it in the unit store's images/ folder. New text ids follow the same scheme (paper prefix, e.g. ab24-t5) and are never reused.
3. HSC check. A text or question from a real HSC paper must never ship. Check each new text's author and title against resources/english-unseen/hsc-texts.json (extend it, with sources), and set hscChecked only after the check. A match is skipped with "hsc_text".
4. Source, qNo (1 to 5), marks (3 to 8), directive verb (nearly always "compare"; Girraween 2025 "most effectively" is "evaluate").
5. Suggested length: count the printed answer lines as answerLines, or null when they cannot be counted; for 7 and 8 marks the median is counted by npm run unseen-report from this unit's papers (do not edit MEDIAN_WORDS by guess).
6. Rubric. Where the paper has marking guidelines, copy the criteria verbatim (origin "school") and use the school's sample answer as the model answer (origin "school"). Otherwise draft NESA-style band descriptors that restate the question's own wording for every mark (origin "drafted") and write a model answer (origin "drafted") that meets, and does not exceed, the schools' full-mark standard: a clear comparative answer to the whole question with both texts treated in depth, about 35 words a mark. On a choice question the model answer covers one pairing: set pairing to its text ids, and the criteria must not require that pairing. Marking notes: "None provided by the school." when there are none.
7. Tags: forms of the texts, 1 to 3 of the nine skills the question most tests (the seven in lib/unseen/skills.json plus compares-texts and treats-both-in-depth), and the syllabus outcome (EAV-12-01, EAV-12-02 or EAV-12-04).
8. A visual text's description (new visuals only; existing ones keep theirs): write it so the marker could mark from it, without quoting the question; it is server-only.

Then:
9. Write resources/english-unseen/bank/comparative/<school>-<year>.json (new texts, plus the questions in the format of data-model.md §9) and run npm run unseen-build-bank.
10. Check every model answer with the real marker: mark each with the unit's marker (lib/comparative/rubric.json, ENGLISH_ADV_GRADING_MODEL, 3 runs). Every model answer must get full marks on the majority of runs, marked with the texts of its own pairing (on a choice question, `pairing`). Revise any that fail and list them. Run npm run check-unseen-descriptions for new visual ids only (a scratch runner limited to them is fine); a visual that fails is removed with its question.
11. Run npm run validate, npm test, npx tsc --noEmit and npm run build through Git Bash, then npm run unseen-report.
12. Stop and give me: questions kept and skipped by paper with the reasons; counts by mark value and by fixed pair / choice; every drafted rubric and model answer with a line saying whether the marker gave it full marks; the pairing of every choice question; any text you were unsure about; the medians counted for 7 and 8 marks; the path to resources/english-unseen/review/report.md and the comparative section of ALL-REVIEW.md (a "Comparative, Batch N" section with every question and an empty [ ] box). Do not set reviewedOn: I tick the boxes and ask you to release.

Lessons from spec 008 to apply: restate the question's own wording in every drafted band; footnotes are "word: definition" with no inline markers; check answerLines against the booklet (more than 12 words a mark of lines is suspect); a model answer that echoes the question's phrases or a school's sample verbatim is fine only where it is the school's sample, credited; new directive verbs need a NESA definition in lib/comparative/rubric.json (list them); the earlier bank files are not touched; text that came from a paper stays verbatim and credited; hscChecked/reviewedOn must not be later than today's UTC date.

Rules: everything copied from the papers stays verbatim and credited; the original PDFs and the bank JSON stay in gitignored resources/; only the generated unit files and cropped images are committed. Use .cline/ for scratch scripts (tmp-<purpose>.<ext>) and delete them at the end. Use Git Bash for every shell command. No new runtime dependency (Python libraries for PDF rendering, OCR or cropping may be installed for this offline task).
```

After the gate has passed and you approve a batch in the review report, tick its boxes in `ALL-REVIEW.md` and ask Claude Code to release the ticked questions (set `reviewedOn`, rebuild, run the full chain, commit and push).
